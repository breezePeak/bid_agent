# 目标流程、数据模型与状态机

## 1. 全量编写流程

必须维持当前页面和当前调用链：

```text
创建普通工作空间
→ 上传招标文件和公司/参考资料
→ 当前流水线
→ 当前目录确认
→ 当前章节工作台
→ 当前一键/批量编写
→ 当前正文编辑与导出
```

## 2. 标书改写流程

```text
创建“标书改写”工作空间
→ 上传新招标书
→ 上传旧投标书
→ 旧投标书独立解析并预览
→ 使用现有新招标解析链生成新目录
→ 用户确认新目录
→ 进入章节工作台
→ 选择叶子章节
→ 系统匹配旧章节/段落
→ 用户查看原文和覆盖情况
→ 用户调整旧段落、补充资料或搜索
→ 用户确认当前章改写方案
→ 开始改写
→ 自动切换到正文
→ 编辑、确认、导出
```

## 3. WorkspaceProfile

```json
{
  "workspace_id": "xxx",
  "project_mode": "full_write | bid_rewrite",
  "created_at": "...",
  "updated_at": "..."
}
```

规则：

- 旧工作空间缺少记录时读取为 `full_write`；
- 创建 API 缺少 `project_mode` 时写入 `full_write`；
- 上传任何材料后禁止切换 mode；
- `full_write` 不读取任何改写状态。

## 4. LegacyBidSourceManifest

```json
{
  "revision": 1,
  "sources": [
    {
      "legacy_bid_id": "legacy-xxx",
      "filename": "旧投标书.docx",
      "mime_type": "...",
      "sha256": "...",
      "version": 1,
      "active": true,
      "stored_path": "workspace/v3/legacy_bid_sources/..."
```

第一阶段只支持一份活动旧投标书。多旧标书留到 PR-06，避免第一轮就把匹配变成材料批发市场。

## 7. 状态机

```text
not_started
→ matching
→ match_ready
→ plan_draft
→ plan_confirmed
→ executing
→ draft_ready
→ formal
```

异常状态：

```text
match_failed
plan_stale
pollution_blocked
execution_failed
```

变化传播：

- 新目录变化：全部章节 match/plan stale；
- 旧投标书替换：全部 match/plan stale；
- 当前章上下文变化：仅当前章 plan stale；
- 未选择的普通参考资料变化：不得让所有改写方案 stale；
- 正文人工编辑：不反向修改已确认的改写方案。



