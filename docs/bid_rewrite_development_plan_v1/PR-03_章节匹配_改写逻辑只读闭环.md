# PR-03：按新章节匹配旧章节/段落，只读改写逻辑闭环

## 1. 唯一目标

目录确认后，用户打开一个新叶子章节，可以在“改写逻辑”中看到系统从旧投标书匹配出的具体章节和段落，并查看建议的改写方式。

本 PR 只读，不允许确认或执行正文。

## 2. 后端

新增：

```text
ChapterRewriteMatchService
chapter_rewrite_match_revisions
bid_rewrite.match.generate
```

### 2.1 匹配目标

使用现有代码生成当前章目标：

```text
Blueprint title
purpose
writing_objectives
requirements
score conditions
compile_chapter_writing_plan().blocks
```

### 2.2 两阶段匹配

```text
第一阶段：
标题、heading_path、关键词、章节层级召回

第二阶段：
读取候选原始 SourceBlock
→ 模型/受控 rerank
→ 返回 exact section_id/block_id/content_hash
```

候选输出必须引用已存在的 ID，伪造引用直接失败。

### 2.3 覆盖分析

对每个 WritingPlan block 标记：

```text
fully_covered
partially_covered
not_covered
conflicted
```

根据覆盖结果计算建议：

```text
copy
light_edit
restructure
new_write
```

建议不是最终用户选择。

## 3. 前端

仅 `bid_rewrite` 工作空间的中间区域显示：

```text
[改写逻辑] [正文]
```

### 改写逻辑只读内容

左侧：

```text
当前章新要求
当前章 WritingPlan blocks
```

中间：

```text
匹配的旧章节/段落
原文预览
匹配理由
覆盖到哪个新写作块
风险提示
```

右侧：

```text
建议策略
已覆盖项
缺失项
```

正文编辑器使用 `v-show` 保持挂载，切页签不能丢未保存正文。

切换章节时取消旧请求，禁止上一章匹配结果串入下一章。

## 5. 自动化测试

- 仅 H1 后可匹配；
- 父章节不可匹配；
- 标题召回；
- 语义召回；
- 最终 rerank 读取原文；
- unknown section/block 被拒绝；
- stale LegacyBidIndex 被拒绝；
- coverage 四状态；
- 四策略建议正反例；
- 两章并发不串结果；
- 快速切章不串响应；
- full_write 不显示页签；
- 页签切换不销毁正文；
- loading/error/no-match 状态。

## 6. 人工验收

1. 选择 5 个新章节；
2. 核对系统匹配的旧章节；
3. 随机检查 20 个段落原文；
4. 检查有旧内容的章节和完全缺失章节；
5. 快速切换章节；
6. 编辑一段正文后切到改写逻辑再返回，内容不丢；
7. 普通全量编写工作空间页面不变化。
