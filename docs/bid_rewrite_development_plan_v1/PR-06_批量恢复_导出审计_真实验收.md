# PR-06：批量改写、恢复、导出审计与真实验收

## 1. 唯一目标

在单章改写稳定后，支持选择多个已确认章节执行改写，支持中断恢复，并完成最终 Word 污染审计和真实项目验收。

## 2. 批量规则

- 仅选择 `plan_confirmed` 且非 stale 的叶子章节；
- 每章冻结自己的 plan revision/hash；
- 一个章节失败不覆盖其他章节结果；
- 失败章节可单独重试；
- 重启后恢复；
- 不允许批量任务绕过污染 Gate；
- 不允许任务启动后自动采用新 match 或新 plan。

## 3. 前端

rewrite 工作台增加：

```text
选择章节改写
全选已确认章节
开始改写 N 章
```

显示：

```text
当前章节
已完成
失败
待处理
阻断原因
```

full_write 原批量按钮和逻辑保持不变。

## 4. 最终导出审计

导出前扫描：

- 旧项目名称；
- 旧采购人；
- 旧地区；
- 旧日期、年份、工期；
- 旧人员；
- 旧系统/产品版本；
- 改写策略标签；
- 内部 block ID/hash；
- 提示词和内部 WritingPlan 文字。

发现阻断项时不得标记正式交付。

## 5. 性能边界

至少验证：

- 1 份 300 页旧 DOCX；
- 1 份 500 页旧 PDF；
- 100 个新叶子章节；
- 单章候选召回耗时；
- 章节切换响应；
- 旧索引重启恢复；
- 批量并发上限；
- SQLite 锁冲突。

## 6. 真实项目验收

至少三套：

1. 原有全量编写项目；
2. 高相似旧标书改写项目；
3. 低相似旧标书改写项目。

每套检查：

```text
新目录覆盖
旧内容匹配准确率
人工删除/增加旧段落量
污染 finding 漏报
正文人工修改量
Word 逐页检查
中断恢复
```

## 7. 自动化测试

- batch frozen plan；
- stale plan 不入队；
- mixed strategies；
- partial failure；
- retry；
- process restart；
- idempotency；
- no cross-chapter sources；
- export pollution audit；
- labels/internal IDs absent；
- full_write batch regression；
- strict template regression；
- service restart；
- final compose/H2/Word。

## 8. Definition of Done

- [ ] 批量改写可恢复；
- [ ] 每章精确绑定确认方案；
- [ ] 最终 Word 无旧项目污染；
- [ ] full_write E2E 正常；
- [ ] 两套 rewrite E2E 正常；
- [ ] 完整 CI 全绿；
- [ ] 真实验收报告完成。
