## 2. 当前真实调用链

### 2.1 创建工作空间

```text
frontend/CreateWorkspaceDialog.vue
→ createRun(name, ...)
→ POST /api/v3/workspaces
→ 创建 workspace/v3 与 outputs/v3
→ ControlStore ACL
```

当前只提交项目名称，没有模式字段。

### 2.2 主材料输入

```text
POST /api/v3/workspaces/{id}/uploads
→ InputRole
→ InputManifestService.register_local_file
→ promoted InputManifest
→ SourceNormalizer
→ promoted SourceIndex
```

当前 InputRole：

```text
tender
score
template
amendment
company
reference
guidance
```

### 2.3 新目录生成

```text
normalize_sources
→ build_requirement_ledger
→ analyze_scores
→ plan_response
→ compile_chapter_blueprint
→ confirm_planning
```

当前角色选择是正向白名单：

- Requirement Agent 只读 `tender/amendment/score`；
- Project understanding 只读 `tender/amendment/company`；
- Score 只读评分来源。

因此旧投标书如果走独立旁路，现有目录链不需要被重构。

### 2.4 章节写作

```text
ChapterAgentService / 单章按钮 / 批量任务
→ ChapterWritingRequest
→ ChapterWritingService
→ WriterInputBundleAssembler
→ 内部 ChapterWritingPlan
→ WriterResearchCoordinator
→ ContentWriter
→ WriterBundleContentGate
→ chapter.generate_draft
```

`ChapterWritingRequest` 已支持：

```text
operation=create|rewrite|repair
user_instruction
chapter_dialogue
chapter_writing_plan
run_research
```

这意味着标书改写不需要新建 Writer，只需要增加一层改写方案装配。

## 3. 可以复用的代码

- `SourceNormalizer` 的 DOCX/PDF/MD/TXT 结构恢复；
- `SourceBlock` 的稳定 block ID、顺序、页面、heading_path 和 content_hash；
- `compile_chapter_writing_plan()` 的新章节目标和 must_answer；
- `ChapterWritingService` 的认证、CAS、研究、ContentWriter、Gate 和草稿提交；
- `ContentBlockEditor`、章节版本、H2 和 Word 导出；
- 现有章节聊天和流式写入；
- Tavily 研究服务和 EvidenceBatch。

## 4. 不能复用为权威状态的内容

- `_writing_plans.json` 不能保存正式改写来源选择；
- 右侧聊天消息不能作为旧段落选择的权威记录；
- 浏览器内存不能保存已确认改写方案；
- 旧投标书 Markdown 预览不能成为原文真相；
- 章节标题相似度不能成为最终复制依据。
