# PR-02：新招标书独立生成新目录，旧标书零污染

## 1. 唯一目标

在标书改写工作空间中，使用现有的新招标解析和目录生成链生成新的简单目录，并完成 H1 确认。

旧投标书不参与目录生成。

## 2. 材料就绪规则

### 全量编写

保持当前规则，不修改。

### 标书改写

必需：

```text
新招标书
旧投标书 LegacyBidIndex ready
```

可选：

```text
独立评分文件
公司资料
参考资料
guidance
template
```

## 3. 目录调用链

```text
新招标书进入主 InputManifest
→ SourceIndex
→ RequirementLedger
→ ScoreModel
→ ProjectModel
→ ChapterBlueprint
→ H1
```

LegacyBidSourceManifest 和 LegacyBidIndex 不出现在该调用链中。

## 4. 零污染审计

新增确定性审计：

```text
RequirementLedger source anchors
ScoreModel source anchors
ProjectModel facts/source refs
ChapterBlueprint requirements/conditions
Outline provider input snapshot
```

均不得包含：

- legacy_bid_id；
- 旧标书文件 hash；
- 旧标书 block ID；
- 旧标书中的专用测试标记词。

旧标书替换不得使：

```text
RequirementLedger
ScoreModel
ProjectModel
ChapterBlueprint
```

因依赖变化而 stale。

## 5. 前端

标书改写流水线显示：

```text
1. 新招标文件解析
2. 评分与项目理解
3. 生成新目录
4. 等待目录确认
```

旧标书解析状态单独显示，不混进新目录步骤。

目录预览中不得出现“来自旧目录”的标签，因为旧目录根本不参与。

## 6. 预计修改文件

```text
frontend/src/components/V3WorkspaceView.vue
frontend/src/api/v3Contracts.js
src/document_pipeline/workspace_snapshot.py
src/document_pipeline/material readiness 相关服务
tests/zero pollution audit
```

原则上不修改：

```text
requirement_agent.py
score_agent.py
planning provider prompt
chapter_blueprint rules
```

除非真实代码检查证明必须修改；任何修改都要证明 full_write 输出不变。

## 7. 自动化测试

- bid_rewrite 缺新招标被阻断；
- bid_rewrite 缺旧标书被阻断；
- company 资料不是 rewrite 必传；
- 新目录覆盖新 Requirement/Score；
- 旧标书专用标记不进入核心 Artifact；
- 替换旧标书不使核心 Artifact stale；
- 替换新招标使目录 stale；
- H1 正常；
- full_write 材料就绪规则不变；
- full_write Golden 目录不变；
- 前端阶段状态和错误提示。

## 8. 人工验收

1. 上传一份新招标书和内容完全不同的旧标书；
2. 生成新目录；
3. 核对目录只响应新招标要求；
4. 替换旧标书，目录不变化、不重新生成；
5. 替换新招标书，目录正确失效；
6. 修改并确认目录；
7. 进入章节工作台，但本 PR 尚不显示旧段落匹配。
