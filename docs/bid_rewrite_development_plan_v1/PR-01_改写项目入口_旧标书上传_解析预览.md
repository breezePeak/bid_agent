# PR-01：改写项目入口、旧标书上传与解析预览

## 1. 唯一目标

用户可以创建“标书改写”工作空间，上传一份旧投标书，并在页面中查看解析出的旧目录和原始段落预览。

本 PR 不生成新目录，不做章节匹配，不写正文。

## 2. 开始条件

- 当前 HEAD 为回退后的基线或其后仅包含经过审查的修复；
- 当前全量 Python、前端测试和 build 通过；
- 原全量编写至少完成一次人工冒烟；
- 旧 PR 计划已标记作废。

## 3. 后端实现

### 3.1 WorkspaceProfile

新增：

```text
ProjectMode = full_write | bid_rewrite
workspace_profiles
ControlStore.workspace_profile()
ControlStore.initialize_workspace_profile()
```

创建 API：

```json
{
  "name": "项目名称",
  "project_mode": "bid_rewrite"
}
```

缺省固定为 `full_write`。

### 3.2 独立旧标书上传

新增专用接口：

```text
POST /api/v3/workspaces/{workspace_id}/legacy-bids
GET  /api/v3/workspaces/{workspace_id}/legacy-bids
GET  /api/v3/workspaces/{workspace_id}/legacy-bids/{legacy_bid_id}/index
```

限制：

- 仅 `bid_rewrite`；
- `.docx/.pdf/.md/.txt`；
- 第一阶段最多一个 active 旧标书；
- 文件进入 `legacy_bid_sources`；
- 不调用 `InputManifestService.register_local_file()`。

即使 `InputRole` 新增 `LEGACY_BID` 供结构模型使用，通用 `/uploads` 也必须明确拒绝该角色，避免旧标书绕路混入主输入。

### 3.3 解析

新增：

```text
LegacyBidSourceService
LegacyBidIndexService
```

允许复用 `SourceNormalizer` 的文件解析函数，但输出为独立 `LegacyBidIndex`。

### 3.4 Artifact

新增：

```text
LegacyBidSourceManifest
LegacyBidIndex
```

更新：

```text
contracts.py
artifact_registry.py
capability_registry.py
gate_policy_registry.py
artifact promotion tests
```

### 3.5 Snapshot

workspace snapshot 增加：

```json
{
  "profile": {"project_mode": "bid_rewrite"},
  "legacy_bid": {
    "status": "not_uploaded | parsing | ready | failed",
    "active_id": "...",
    "section_count": 0,
    "block_count": 0,
    "needs_review_count": 0
  }
}
```

## 4. 前端实现

### 4.1 创建弹窗

显示两个模式卡片：

```text
全量编写
沿用当前完整生成流程

标书改写
使用新招标书和旧投标书逐章改写
```

默认选中全量编写。

### 4.2 上传区

`bid_rewrite` 工作空间新增独立旧标书上传卡：

```text
旧投标书（必传）
```

不能混进“公司资料/参考资料”。

### 4.3 解析预览

上传后展示：

```text
解析状态
目录层级
章节数量
段落数量
结构缺口
```

目录可展开，点击段落显示原文、页码、block ID 和 hash 短值。

## 6. 自动化测试

- 创建请求缺 mode 默认 `full_write`；
- 旧工作空间读取为 `full_write`；
- `bid_rewrite` 正确持久化；
- `full_write` 专用旧标书上传返回明确错误；
- 通用 `/uploads` 拒绝 legacy bid；
- 旧标书未进入 InputManifest；
- 旧标书未进入 SourceIndex；
- DOCX/PDF/MD/TXT 结构解析；
- 同名标题、跳级标题、无标题段落；
- block ID/hash 稳定；
- 替换旧标书使旧索引 stale；
- Artifact Gate/Promotion；
- 创建 UI 两模式；
- 全量编写旧创建流程回归；
- 前端上传/预览状态。

## 7. 人工验收

1. 创建一个普通工作空间，页面与以前一致；
2. 创建一个标书改写工作空间；
3. 上传旧 DOCX；
4. 页面显示旧目录；
5. 随机打开 10 个段落，与 Word 原文核对；
6. 刷新页面，解析结果仍在；
7. 替换旧标书，旧索引失效并重建；
8. 返回普通工作空间，不出现旧标书上传卡。
