# 后端实现计划：按文件、类与接口拆解

## 1. 实现原则

后端改造按“契约 → 存储 → 服务 → API → 调用方”的顺序完成。  
每一层先完成单测，下一层才可引用。不能先让前端调用一个还准备下周再写的接口，这类开发方式对报错数量确实很有追求。

## 2. `src/document_pipeline/contracts.py`

### 2.1 新增项目写作模式

```python
ProjectWritingMode = Literal["full_write", "bid_rewrite"]
```

不要修改当前：

```python
DocumentMode = Literal["template_strict", "auto_outline"]
```

### 2.2 扩展 `InputRole`

```python
class InputRole(str, Enum):
    ...
    LEGACY_BID = "legacy_bid"
```

需要同步：

- 上传角色校验；
- 前端上传选项；
- 输入清单展示；
- Source normalizer role；
- 输入前置条件 Gate；
- 测试 fixtures；
- 任何 exhaustiveness mapping。

### 2.3 LegacyBidIndex 模型

新增：

```text
LegacyEntityRisk
LegacyBidDocument
LegacySectionProfile
LegacyParagraphProfile
LegacyIndexCoverage
LegacyBidIndex
```

全部 `extra="forbid"`，字符串 trim，ID 唯一，parent 无环由 model validator 或 Gate 检查。

### 2.4 Blueprint lineage

新增：

```text
OutlineLineageDecision
OutlineLineageRef
BlueprintNode.outline_lineage
```

默认空数组，保证旧 payload 可读取。

### 2.5 Chapter plan 模型

新增：

```text
ChapterPlanConstraints
ChapterPlanContentUnit
ChapterPlanSourceRef variants
ChapterPlanSource
ChapterPlanBinding
ChapterPlanExclusion
ChapterPlanResearchDecision
ChapterWritingPlanPayload
ChapterPlanProposalPayload
ChapterPlanApprovalReceiptModel
```

建议使用 discriminated union 表示 source ref：

```python
LegacyParagraphSourceRef
WebEvidenceSourceRef
ProjectFactSourceRef
UploadedBlockSourceRef
```

避免一个 `dict[str, Any]` 让所有错误都推迟到运行时。

### 2.6 WriterInputBundle

增加可选兼容字段，默认值保证旧 Bundle fixture 可解析：

```python
chapter_plan_revision: int = 0
chapter_plan_hash: str = ""
chapter_plan_approval_receipt_id: str = ""
chapter_plan_snapshot: dict[str, Any] = {}
selected_source_blocks: list[dict[str, Any]] = []
selected_source_bindings: list[dict[str, Any]] = []
excluded_source_refs: list[str] = []
```

当 `chapter_plan_revision > 0` 时 model validator 强制：

- plan hash 非空；
- approval receipt 非空；
- plan snapshot 非空；
- dependency fingerprint 包含 plan。

## 4. 输入与上传链路

### 4.1 `src/api/v3_app.py` 创建工作空间

当前创建接口只取 `name`。改为严格请求解析：

```python
class CreateWorkspaceRequest(BaseModel):
    name: str
    writing_mode: ProjectWritingMode = "full_write"
    project_type: str = ""
    expected_pages: int | None = Field(default=None, ge=1, le=5000)
```

流程：

1. 解析并校验；
2. 创建临时工作空间目录；
3. 初始化 `ControlStore`；
4. 原子写 `document_state`；
5. 授予 ACL；
6. 写 workspace event；
7. 返回完整 profile；
8. 任一步失败清理临时目录。

### 4.2 上传

`_validate_upload_type` 对 `LEGACY_BID` 使用与 tender/reference 相同的可解析扩展名集合，但角色规则独立。

### 4.3 规划前置校验

不要在用户上传第一份文件时就要求所有文件齐全。  
在 `document.prepare_outline` handler 之前校验：

```text
full_write:
  active tender >= 1

bid_rewrite:
  active tender >= 1
  active legacy_bid >= 1
  LegacyBidIndex active and matches SourceIndex
```

错误：

```text
LEGACY_BID_REQUIRED
LEGACY_BID_INDEX_NOT_READY
LEGACY_BID_INDEX_STALE
```

## 7. `prompts/v3_planning_agent_blueprint.md`

增加受控规则：

1. 新招标与评分决定内容边界；
2. 旧目录只作结构候选；
3. 可保留、改名、合并、拆分或忽略；
4. 不复制旧项目名称和年份；
5. 不因旧目录存在就新增无评分/需求依据的根章节；
6. auto outline 才可调整层级；
7. template strict 不得改模板 topology；
8. 每个 lineage 只能引用输入提供的稳定 ID；
9. 输出仍只包含 Schema，不输出解释；
10. 不写正文、不访问旧正文内容。

增加 prompt golden tests，防止后续一句“优化提示词”把权威边界又优化没了。

## 8. 新增章节规划模块

建议文件：

```text
chapter_writing_plan.py
chapter_plan_proposals.py
chapter_plan_validation.py
chapter_plan_gate.py
chapter_plan_promotion.py
chapter_plan_staleness.py
chapter_plan_sources.py
chapter_plan_research.py
chapter_rewrite_classifier.py
```

### 8.1 `ChapterWritingPlanService`

```python
class ChapterWritingPlanService:
    def get(self, chapter_id: str) -> dict
    def build_iter_events(self, request: ChapterPlanBuildRequest)
    def save_user_revision(self, request: ChapterPlanEditRequest)
    def confirm(self, request: ChapterPlanConfirmRequest)
    def reject(self, request: ChapterPlanRejectRequest)
    def mark_stale(...)
```

### 8.2 Build 顺序

```text
load workspace capability
load chapter + Blueprint slice
load chapter semantics
compile stable content units
collect project/local sources
if bid_rewrite: retrieve legacy candidates
assess evidence gaps
if needed: run research and fetch original
construct bindings
compute rewrite type
validate
persist proposal
gate
promote draft revision
emit plan_ready
```

### 8.3 用户编辑

用户不能直接 PUT 任意 canonical payload。流程：

1. API 接收受限 edit operations；
2. Service 加载 base plan；
3. 应用 operation；
4. 重算来源、类型、hash 和依赖；
5. 生成新的 user-edit proposal；
6. validation/gate；
7. promotion 新 draft revision。

允许操作：

```text
add_source
remove_source
move_source
bind_source
unbind_source
update_binding_instruction
add_content_unit
update_content_unit
remove_content_unit
move_content_unit
add_exclusion
remove_exclusion
```

不允许修改：

```text
chapter_id
blueprint revision/hash
source raw content
source hash
requirement ownership
score ownership
```

## 9. 来源 Provider

### 9.1 `TenderConstraintProvider`

从本章 requirement/scoring projection 生成只读来源卡片和 constraints，不将评分原文机械写入正文。

### 9.2 `ProjectMaterialProvider`

从：

- ProjectModel；
- GlobalProjectContext；
- ChapterContext；
- active company/reference/guidance 输入；
- material verification；

生成候选 source。

### 9.3 `LegacyBidSourceProvider`

仅在 `bid_rewrite` 启用：

```python
def search_candidates(
    chapter,
    content_units,
    legacy_index,
    source_index,
    limit_per_unit,
) -> list[LegacyCandidate]
```

返回具体 paragraph `block_id`，不是只返回章节摘要。

### 9.4 `WebEvidenceProvider`

复用现有 research services，但职责变为：

- 判断查询；
- 搜索；
- 获取原文；
- 生成/读取 immutable EvidenceItem；
- 返回 plan source。

不直接触发 Writer。

## 11. `writer_research.py` 与研究服务

### 11.1 新旧双路径

```text
legacy capability:
  ChapterWritingService → WriterResearchCoordinator.prepare → Writer

plan capability:
  ChapterWritingPlanService → ChapterPlanResearchCoordinator → confirm
  ChapterWritingService → no research → Writer
```

### 11.2 禁止重复研究

新路径写作请求若：

```python
run_research is True
```

服务端返回：

```text
CHAPTER_WRITE_RESEARCH_NOT_ALLOWED
```

不要静默忽略，否则调用方以为执行了搜索。

### 11.3 原文门禁

Web source 进入 plan 必须满足：

```text
fetch_status = ready
snapshot_id/hash 非空
content 非空或合法结构化片段
```

`lead_only` 只能显示候选，不能绑定为 Writer source。

## 12. `writer_bundle.py`

### 12.1 Assemble 新签名

```python
def assemble(
    ...,
    confirmed_plan: ChapterWritingPlanPayload | None = None,
    plan_approval_receipt: dict | None = None,
    compatibility_mode: bool = False,
) -> WriterInputBundle:
```

### 12.2 新路径

1. 读取 confirmed plan；
2. 验证 plan hash；
3. 验证 receipt；
4. 根据 source ref 精确读取：
   - SourceBlock；
   - EvidenceItem；
   - Project fact；
   - Chapter context item；
5. 检查 source hash；
6. 构造 selected sources；
7. 生成 `allowed_source_ids`；
8. 冻结 plan snapshot；
9. 计算 Bundle hash。

### 12.3 不得继续按章节宽泛收集 Evidence

当前 `_evidence_snapshot()` 按 chapter/score/requirement 收集相关证据。新路径必须只取确认 plan 中的 ID。

用户删掉来源后，它不能因为“仍然相关”又从后门回来。

## 13. `chapter_writing_service.py`

### 13.1 `ChapterWritingRequest` 增加

```python
plan_revision: int = 0
plan_hash: str = ""
plan_approval_receipt_id: str = ""
idempotency_key: str = ""
```

### 13.2 验证分支

```python
if capability.plan_required_for_write:
    _validate_confirmed_plan_authority()
    require run_research is False
else:
    _validate_outline_authority()
```

### 13.3 `_validate_confirmed_plan_authority`

验证：

- plan revision 是当前 confirmed；
- hash 匹配；
- receipt 匹配；
- dependency 未变化；
- chapter revision 没有非法覆盖；
- plan status 不是 stale；
- rewrite type 与 payload 一致；
- 所有 selected source 可读且 hash 匹配。

### 13.4 写作过程

```text
validate
assemble exact bundle
emit drafting
call ContentWriter
grounding gate
legacy contamination gate
content gate
append content revision with plan refs
emit done
```

### 13.5 资料缺口

Writer 或 pre-write gate 发现缺口：

```text
raise CHAPTER_PLAN_REVISION_REQUIRED
details:
  missing_questions
  affected_content_units
  suggested_search_queries
```

不调用研究工具。

## 16. `chapter_batch.py`

### 16.1 创建门禁

新能力工作空间只接受：

```text
plan confirmed
plan not stale
chapter active
not already running
```

队列冻结：

```text
plan_revision
plan_hash
approval_receipt
chapter_revision
```

### 16.2 执行门禁

每个 item 开始前重验。失败不阻止其他独立章节，但记录：

```text
CHAPTER_BATCH_PLAN_STALE
CHAPTER_BATCH_PLAN_REQUIRED
CHAPTER_BATCH_SOURCE_STALE
```

### 16.3 恢复

服务重启恢复时：

- 已完成项不重复；
- running 无 lease 项重置为 queued/retry；
- plan stale 项标 blocked；
- 用户重新确认后允许 retry；
- 幂等 writer command 防止重复 content revision。

## 20. 后端 Definition of Done

- 所有新增 Schema `extra=forbid`；
- Agent 无 direct write；
- Proposal/Gate/Promotion 测试；
- CAS、重放、并发测试；
- 旧路径 Flag off 全绿；
- 新路径禁止 inline research；
- Bundle 来源精确等于 plan；
- 旧标书污染门可阻断；
- API 幂等；
- 事件流断线重试不重复；
- 批量任务不绕过 plan；
- 快照不泄露大正文；
- CI 全绿。
