# 分阶段 PR 任务清单、依赖顺序与验收门禁

## 1. 总原则

每个 PR 必须：

1. 可独立部署；
2. 有默认关闭或兼容行为；
3. 不依赖“下一 PR 才会补”的字段；
4. 自带测试；
5. 自带回滚说明；
6. 不同时跨越过多层；
7. CI 全绿后才合并；
8. 合并后在真实工作空间副本做 smoke。

---

## 2. PR 依赖图

```text
PR0 基线保护
 └─ PR1 契约/项目模式
     └─ PR2 计划控制面
         ├─ PR3 全量影子规划
         │   └─ PR4 前端只读规划
         │       └─ PR5 确认与 Writer 精确消费
         │           └─ PR6 全量新链路灰度
         └─ PR7 LegacyBidIndex
             └─ PR8 新旧目录融合
                 └─ PR9 旧段落规划与四类改写
                     └─ PR10 批量/陈旧/导出
                         └─ PR11 韧性/性能/质量
                             └─ PR12 发布切换
```

PR7 可以在 PR3-6 后端稳定期间并行开发，但不能在 PR2 之前合并到主线的新行为。


## 17. 禁止跨 PR 的“临时状态”

不允许合并：

- 前端读取后端尚未返回的必填字段；
- DB head 指针没有 revision 表；
- plan confirm 没有 receipt；
- Writer 先要求 plan，但 UI 还不能确认；
- bid_rewrite 可创建但没有明确 blocked 页面；
- 新 prompt 输出字段未进入 Schema；
- batch 先启用但没有 plan check；
- 旧路径先删除再等新路径稳定。

每个 PR 合并后的主分支必须仍是完整可运行系统，不是半座等着下个周末来补的桥。
