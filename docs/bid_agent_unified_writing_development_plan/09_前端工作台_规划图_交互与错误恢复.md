# 前端工作台、规划图、交互与错误恢复详细计划

## 1. 目标

在当前 `ChapterWorkbenchView.vue` 中间区域增加可切换页签：

```text
[编写逻辑] [正文]
```

保持左侧章节树和右侧章节 Agent，不新建工作台。

## 4. 中间双页签

### 4.1 页面结构

```vue
<section class="chapter-center">
  <nav class="chapter-center__tabs">
    <button>编写逻辑</button>
    <button>正文</button>
  </nav>

  <ChapterWritingPlanPanel v-if="centerTab === 'plan'" />
  <ContentBlockEditor v-else />
</section>
```

### 4.2 默认切换

选择章节后：

```js
if (chapter.hasValidDraft) centerTab = 'content'
else centerTab = 'plan'
```

规划生成完成不自动切正文。  
正文生成成功后自动切正文。

### 4.3 用户手动选择优先

同一章节会话中用户手动切换后，不因一次普通 snapshot 刷新强行切回。只有：

- 首次进入；
- 新正文生成成功；
- 当前页签已不可用；

才自动切。

## 5. 左侧章节标签

```js

```

显示：

实现要求：

- badge 独立 DOM，不拼入 title；
- 搜索/排序使用原 title；
- 编辑标题不包含 badge；
- 导出不包含 badge；
- tooltip 显示分类理由；
- 全量编写项目可不显示 rewrite badge，或显示“全量编写”由产品决定，第一版建议不显示。

## 6. 规划图布局

### 6.1 三列

```text
来源材料          计划内容块          当前章节
```

固定有向布局，不需要自由拖动节点。

### 6.2 连线

第一版：

- CSS Grid 放节点；
- 容器内 SVG overlay；
- 根据元素 `getBoundingClientRect()` 计算端点；
- `ResizeObserver` 监听；
- 展开/折叠、窗口 resize、滚动后节流重绘；
- 点击线选中 binding；
- hover 高亮两端。

### 6.3 大图降级

节点超过阈值：

- 来源按 section/类型折叠；
- 默认只展开当前 content unit；
- 提供列表模式；
- 不一次渲染几千段；
- 来源详情按需请求原文。

### 6.4 不能保存坐标

布局坐标只在浏览器计算。canonical plan 不存前端坐标。

## 10. 工具栏

按钮：

```text
生成编写规划
重新分析
继续搜索
仅使用现有资料
规划历史
确认编写规划
开始编写
```

可用条件：

| 按钮 | 条件 |
|---|---|
| 生成 | missing/failed/stale |
| 重新分析 | 有 plan 且不在运行 |
| 继续搜索 | draft，存在 research need |
| 仅使用现有资料 | 非 blocking gap 或用户有权限接受 |
| 确认 | draft + Gate pass + 无 dirty 本地修改 |
| 开始编写 | confirmed + not stale + receipt valid |
| 规划历史 | 至少一个 revision |

## 11. 结构化开始编写

当前不要再：

```js
chatInput.value = '开始编写本章正文'
sendChat()
```

改为：

```js
streamChapterDraft(runId, chapterId, {
  action: 'execute_confirmed_plan',
  plan_revision: plan.plan_revision,
  plan_hash: plan.plan_hash,
  plan_approval_receipt_id: plan.approval_receipt_id,
  expected_chapter_revision: chapter.chapter_revision,
  idempotency_key: crypto.randomUUID(),
})
```

右侧聊天可以记录操作结果，但不负责猜动作。

## 13. 错误隔离

章节详情、规划、聊天、正文是四个独立请求。任一失败不能让整个工作台白屏。

### plan 加载失败

- 正文仍可查看编辑；
- 编写逻辑页显示错误；
- 提供重试；
- 不把 plan 置空后误显示“未生成”。

### 正文加载失败

- 规划仍可查看；
- 显示正文错误；
- 不影响 plan 确认。

### 聊天失败

- 中间区域继续工作；
- 聊天局部提示；
- 不阻止结构化“开始编写”。

### snapshot 流断开

- 显示连接状态；
- 指数退避重连；
- 不重复确认/生成；
- GET snapshot 校准。

## 14. 并发冲突

服务端 409：

```text
CHAPTER_PLAN_REVISION_CONFLICT
```

前端：

1. 保留 `dirtyEdits`；
2. 获取最新 plan；
3. 展示变更摘要；
4. 尝试按 operation ID 重放非冲突编辑；
5. 冲突字段让用户选择；
6. 不直接覆盖。

第一版可提供“复制我的修改说明”而不做复杂三方合并，但绝不能静默丢失。

## 22. 性能控制

- Plan 数据按章加载；
- source 原文按需加载；
- 规划图节点虚拟/折叠；
- resize 重绘节流；
- SVG path 不做昂贵动画；
- snapshot 只传 summary；
- `shallowRef` 避免大对象深响应；
- 切章请求 abort；
- 缓存最近若干章，限制内存；
- 100 节点基准测试。

## 23. 可访问性与可理解性

- 节点和线可键盘选择；
- 颜色之外使用文字和图标区分类型；
- source 风险有文本；
- loading 不锁死整个页面；
- 错误给出下一步；
- tooltip 不承载唯一信息；
- 规划图提供列表视图；
- 中文术语统一，不同时出现“提纲、方案、规划、逻辑”四个词指同一对象：
  - 页面固定叫“编写逻辑”
  - 数据对象叫 `ChapterWritingPlan`
  - 用户按钮叫“确认编写规划”
