# 开发执行守则、PR 模板与代码审查清单

## 1. 使用方式

每次交给 Codex、开发者或 Agent 执行一个 PR 时：

1. 只提供该 PR 的目标；
2. 指定基线 commit；
3. 附上本文件；
4. 附上对应详细计划文件；
5. 要求先读当前代码和测试；
6. 未通过当前 PR 门禁不得开始下一个 PR。

不要一次丢出“把全部功能做完”的提示。模型和人类都很容易在巨大任务里发明一条看似完整、实际绕开现有架构的捷径。

---

## 2. 开发前固定步骤

```text
1. git status，工作区必须清楚
2. 记录 HEAD
3. 阅读相关 ADR
4. 阅读当前实现文件
5. 阅读对应现有测试
6. 画出当前调用链
7. 列出本 PR 会修改的契约
8. 先写失败测试
9. 再写最小实现
10. 运行局部测试
11. 运行全套 CI
12. 做真实工作空间 smoke
13. 更新文档和完成清单
```

---

## 3. 必读 ADR/约束

每个相关 PR 至少复核：

```text
ADR-01 Agent/Artifact/Service 权限
ADR-02 Proposal/Gate/CAS/Promotion
ADR-04 ChapterBlueprint/WriterInputBundle
ADR-07 single planning confirm
ADR-11 exact proposal receipt binding
ADR-12 canonical SourceBlock identity
ADR-14 Blueprint 单向权威（仓库存在时）
ADR-15 真实标书可用性门（仓库存在时）
```

若实现与 ADR 冲突：

- 不偷偷绕过；
- 先写 ADR 变更提案；
- 未批准前按现有 ADR。

---

## 4. 硬性禁止

- 禁止 Agent 直接写 canonical。
- 禁止 Writer 联网。
- 禁止 Writer 读整个 workspace。
- 禁止把旧标书当 ProjectModel。
- 禁止用页码/数组索引替代 `block_id`。
- 禁止计划确认后继续搜索。
- 禁止前端自己计算并保存 canonical rewrite type。
- 禁止在导出 title 中拼 badge。
- 禁止删除旧路径后再补兼容。
- 禁止一个 PR 混合 DB、Prompt、UI、Writer 全量切换。
- 禁止修改测试来迎合错误行为。
- 禁止 catch `Exception` 后返回成功。
- 禁止用无限超时掩盖死锁。
- 禁止修改 active revision 而不留 history。
- 禁止没有 idempotency 的长任务。
- 禁止手工改用户 control.db 作为正常迁移方案。

---

## 5. 代码实现协议

### Schema

- Pydantic `extra=forbid`；
- 所有 ID 非空；
- 默认字段兼容旧 payload；
- discriminated union 优先；
- validator 有单测；
- canonical hash 不包含不稳定时间戳。

### ControlStore

- 事务；
- CAS；
- append-only；
- head 最后更新；
- event 同事务；
- idempotency；
- clear error code；
- migration 幂等。

### Service

- Agent output 先验证；
- 不把 UI payload 直接持久化；
- 所有 source ref 服务端重读；
- 权限检查；
- dependency recheck；
- 失败无半提交。

### API

- 严格 body；
- 兼容旧字段；
- 结构化 error；
- timeout/stream；
- CSRF/ACL；
- idempotency；
- 不返回不必要全文。

### 前端

- API 状态局部隔离；
- 不深响应巨大 payload；
- 不把 canonical plan 本地原地改后冒充已保存；
- 409 保留用户输入；
- Flag off 回归；
- badge 与 title 分离；
- 所有 loading 有结束路径。

## 6. 每次修改后的命令

后端局部：

```bash
python -m pytest tests/test_target.py -q --tb=line
ruff check src tests --quiet
python -m compileall -q src
```

后端全量：

```bash
python -m pytest tests -q --tb=line -k "not live_llm"
```

前端：

```bash
cd frontend
npm ci
npm test
npm run build
```

不得只运行自己新增的一个测试。

## 8. Commit 规范

建议一个 PR 内按可审查顺序：

```text
test: lock current behavior
feat: add contracts
feat: add control storage
feat: add service
feat: add api
feat: add frontend
test: add integration regression
docs: update plan
```

不要一个 20 万行 commit 叫：

```text
fix
```

那不是版本历史，是对后人的敌意。

## 9. 代码审查清单

### 架构

- [ ] 是否新建了重复 Writer？
- [ ] 是否绕过 Bundle？
- [ ] 是否让 Agent 写 canonical？
- [ ] 是否把 plan 塞进 Blueprint？
- [ ] 是否破坏 H1？
- [ ] 是否保留章节隔离？

### 数据

- [ ] ID 稳定？
- [ ] hash 精确？
- [ ] dependency 完整？
- [ ] append-only？
- [ ] stale？
- [ ] rollback？

### 来源

- [ ] SourceBlock canonical？
- [ ] 搜索原文？
- [ ] 用户删除来源真的删除？
- [ ] 旧实体风险？
- [ ] 未确认来源是否可能进入 Writer？

### API

- [ ] 旧调用？
- [ ] 409？
- [ ] idempotency？
- [ ] ACL/CSRF？
- [ ] payload size？
- [ ] error remediation？

### UI

- [ ] Flag off？
- [ ] error isolation？
- [ ] loading？
- [ ] stale？
- [ ] title badge？
- [ ] large data？

### 测试

- [ ] 测试先失败过？
- [ ] 覆盖成功和失败？
- [ ] concurrency？
- [ ] old workspace？
- [ ] full CI？

## 10. 真实工作空间 Smoke 模板

每个改变写作链路的 PR：

```text
工作空间 A：旧 full_write
  打开 → 聊天 → 写一章 → 编辑 → 确认 → 导出

工作空间 B：新 full_write
  规划 → 确认 → 写一章 → 删除来源验证 → 导出

工作空间 C：bid_rewrite（功能阶段到达后）
  legacy index → 融合目录 → plan → 四类之一 → write → 污染检查
```

记录：

```text
workspace fixture version
schema
flags
commit
operation IDs
result
screenshots/diagnostic
```

## 11. Bug 处理规则

发现跨阶段 bug：

1. 停止下一 PR；
2. 写最小复现；
3. 定位首次引入 commit；
4. 判断数据是否受影响；
5. 修复或 revert；
6. 加回归测试；
7. 重跑当前阶段全部门禁；
8. 更新风险和计划。

不要在后续 PR 顺手补。顺手补通常意味着顺手再引入两个。

---

## 12. Prompt 修改规则

任何 prompt 修改必须：

- 版本号；
- Schema 不变或同步；
- golden fixtures；
- 输入/输出 token 预算；
- old/full/bid 对比；
- 非法 ID 测试；
- prompt injection 测试；
- 质量评估。

Prompt 不是无需测试的“文案”。

---

## 13. LLM 降级规则

LLM 不可用：

- 不伪造成功 plan；
- 保存 operation failure；
- 保留 deterministic content units；
- 可让用户重试；
- 已有 confirmed plan 仍可写；
- 不用旧未确认 plan 冒充；
- 不自动扩大权限。

---

## 14. 完成声明模板

只有满足：

```text
实现完成
+ 本 PR 测试全绿
+ 全量回归全绿
+ 真实工作空间 smoke
+ Feature Flag/rollback 验证
+ 文档更新
```

才可声明完成。

不能以：

```text
代码已经写了，暂时没跑
```

作为完成。那只是把错误从开发机搬到了未来。
