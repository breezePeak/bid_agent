# 灰度发布、监控、回滚与运维手册

## 1. 发布原则

- 新能力不直接全量替换；
- 全局 Flag 与工作空间 capability 双重控制；
- 旧工作空间默认兼容；
- 数据迁移增量；
- 回滚优先关闭行为，不删数据；
- 每个灰度阶段至少覆盖完整写作闭环；
- 任何 P0/P1 立即停止扩容。

---

## 2. Feature Flag 设计

建议全局配置：

```text
BID_AGENT_CHAPTER_PLAN_ENABLED
BID_AGENT_PLAN_SHADOW_MODE
BID_AGENT_PLAN_REQUIRED_FOR_WRITE
BID_AGENT_BID_REWRITE_ENABLED
BID_AGENT_LEGACY_INLINE_RESEARCH_ENABLED
```

工作空间 capability：

```json
{
  "chapter_plan_v1": true,
  "plan_shadow": false,
  "plan_required_for_write": true,
  "bid_rewrite_v1": false,
  "legacy_inline_research": false
}
```

有效能力：

```text
effective = global flag AND workspace capability
```

### 合法组合

| plan enabled | shadow | required | bid | 含义 |
|---:|---:|---:|---:|---|
| 0 | 0 | 0 | 0 | 完整旧链路 |
| 1 | 1 | 0 | 0 | 影子规划 |
| 1 | 0 | 1 | 0 | 新全量链路 |
| 1 | 0 | 1 | 1 | 全量+改写 |
| 0 | 任意 | 1 | 任意 | 非法配置，启动诊断并将 required 视为 false |

## 3. 灰度阶段

### 阶段 A：开发/测试环境

- 所有 Flag 开；
- 使用 fixtures；
- 故障注入；
- 数据库迁移；
- 无真实用户。

### 阶段 B：内部影子

- plan enabled；
- shadow=true；
- required=false；
- Writer 仍旧路径；
- 比较：
  - 搜索查询；
  - 来源；
  - 时间；
  - coverage；
  - 错误率。

### 阶段 C：内部新全量链路

- 仅新建测试 workspace；
- plan required；
- legacy inline research off；
- 人工检查 Bundle；
- 完整导出。

### 阶段 D：新建 full_write 小流量

建议：

```text
5% → 25% → 50% → 100%
```

每一级至少观察完整项目周期，而不是看十分钟没报错就宣布胜利。

### 阶段 E：bid_rewrite 内部

- 多种旧标书；
- 真实大文件；
- 目录融合；
- 四类改写；
- 污染检查。

### 阶段 F：bid_rewrite 白名单

- 明确用户；
- 每个项目可一键关闭 capability；
- 收集 plan edits 和失败原因。

### 阶段 G：正式可选

创建项目显示两种模式。旧 workspace 不强制迁移。

结构化字段：

```json
{
  "event": "chapter_plan_promoted",
  "workspace_id": "...",
  "chapter_id": "...",
  "operation_id": "...",
  "plan_revision": 3,
  "plan_hash_prefix": "...",
  "writing_mode": "bid_rewrite",
  "rewrite_type": "light_edit",
  "source_counts": {
    "legacy": 4,
    "web": 1,
    "project": 2
  },
  "duration_ms": 1234,
  "result": "success"
}
```

不记录：

- API Key；
- 完整正文；
- 完整旧投标书；
- Web 全文；
- 用户密码/CSRF；
- 无必要的个人信息。

需要正文诊断时，生成用户主动下载的受控诊断包。

## 6. 告警建议

### P0

- canonical 数据损坏；
- Writer 绕过 plan；
- 跨工作空间/跨章节数据泄露；
- 导出包含敏感内部信息；
- 旧工作空间大面积打不开；
- DB migration 导致数据丢失。

### P1

- plan required 但无法确认；
- 新写作成功率持续明显下降；
- 大量污染 Gate 命中且无法恢复；
- 批量重复生成正文；
- receipt 重放被接受；
- H1 权威破坏。

### P2

- 某搜索 provider 失败；
- 某类 PDF 结构恢复差；
- 规划图性能下降；
- 局部 UI 错误。

## 7. 快速回滚

### 7.1 全量新链路异常

全局：

```text
BID_AGENT_PLAN_REQUIRED_FOR_WRITE=false
BID_AGENT_LEGACY_INLINE_RESEARCH_ENABLED=true
```

工作空间：

```json
{
  "plan_required_for_write": false,
  "legacy_inline_research": true
}
```

保留 plan 表和历史。旧全量写作恢复。

### 7.2 标书改写异常

```text
BID_AGENT_BID_REWRITE_ENABLED=false
```

行为：

- 已创建 bid_rewrite workspace 只读打开；
- 不允许新规划/写作；
- 已有正文可导出；
- 显示维护提示；
- 不隐式切 full_write。

### 7.3 前端规划图异常

关闭前端 plan UI Flag，继续通过旧工作台。后端 plan 数据保留。

### 7.4 migration 异常

- 停止服务；
- 恢复备份；
- 使用旧 commit；
- 关闭 Flag；
- 检查 quick_check；
- 记录失败数据库副本用于分析。

---

## 8. 回滚不能做的事

- 不删除新增表；
- 不把 plan-generated content 改写成“旧路径生成”；
- 不清除 receipts；
- 不覆盖损坏数据库原件；
- 不在用户工作空间直接手工改 JSON；
- 不让 bid_rewrite 静默变 full_write；
- 不用关闭 Gate 作为临时恢复。

---

## 9. 发布前备份

脚本应：

1. 枚举工作空间；
2. 跳过正在删除；
3. 读取 schema/version；
4. 获得维护锁或确认无 active writer；
5. 使用 SQLite backup；
6. 保存 Artifact active pointers；
7. 保存 settings flags；
8. 计算 SHA-256；
9. 输出 manifest；
10. 验证可恢复。

备份路径示例：

```text
backups/2026-08-21-release-x/
  workspace-id/
    control.db
    artifact_manifest.json
    backup_manifest.json
```

## 11. 事故处置手册

### 11.1 `CHAPTER_PLAN_STALE` 激增

检查：

- Blueprint 是否被无意重建；
- global context 是否每次读取都变 hash；
- SourceIndex 是否非确定性排序；
- evidence snapshot 是否每次新 ID；
- canonicalization version；
- plan dependency 是否包含不稳定字段如时间戳。

禁止直接关闭 stale 校验。

### 11.2 `CHAPTER_PLAN_HASH_MISMATCH`

检查：

- 前端是否发送旧缓存；
- JSON canonicalization；
- API 是否修改 payload；
- plan history head；
- 两个标签页并发。

恢复：刷新最新 plan，保留本地编辑，不改数据库 hash。

### 11.3 旧实体污染

检查：

- Legacy risk index；
- binding forbidden carryovers；
- Bundle；
- Writer prompt；
- post gate。

不要只在最终文本 `replace()` 项目名，这会漏掉工期、地点、人员和参数。

### 11.4 搜索来源只有摘要

检查：

- fetch adapter；
- `fetch_status`；
- source Gate；
- fallback 是否错误地把 snippet 标 ready。

关闭该 provider 的 ready 转换，已有 lead 不进入 Writer。

### 11.5 规划图白屏

- 查看 plan API；
- source payload size；
- JS error；
- SVG observer；
- 使用列表 fallback；
- 关闭图 Flag，不影响正文。

### 11.6 批量重复正文

- idempotency key；
- checkpoint；
- recovery；
- content revision；
- operation lease。

立即暂停 batch，不删除 revision，检查重复 hash。

## 12. 诊断包

用户主动导出，包含：

```text
workspace profile
schema version
effective capabilities
active artifact revisions/hashes
chapter workspace summary
plan revisions metadata
receipt metadata
operation/event tail
error codes
source ID/hashes（不含全文或可选脱敏）
frontend build version
backend commit
```

可选包含指定章节的脱敏 plan payload。默认不含旧标书全文。

## 13. 两个发布周期后的清理评估

只有满足：

- 新 full_write 稳定；
- bid rewrite 稳定；
- 旧 workspace 无依赖；
- rollback 不再需要旧 authority review；
- 测试覆盖新路径；
- 用户数据迁移方案明确；

才提出独立 ADR/PR 清理：

- inline research；
- chat outline formal authority；
-旧 API 字段。

本次开发不删除。
