# 测试策略、回归矩阵、故障注入与性能计划

## 1. 测试目标

本次测试不是证明“新功能能跑一次”，而是证明：

1. 新功能在两种模式下流程闭环；
2. 现有全量编写在 Feature Flag 关闭时行为不变；
3. 旧工作空间迁移后仍能打开、写作、确认和导出；
4. 规划确认与 Writer 输入精确一致；
5. 失败、并发、断线和重启不会产生半状态；
6. 旧投标书不会污染新项目；
7. 目录融合不破坏评分和招标覆盖；
8. 批量任务不能绕过规划确认；
9. 数据库 migration 可重复、可恢复；
10. 性能能承受真实长标书，而不是只在三段示例文本里表现英勇。

---

## 2. 基线 CI 门禁

每个 PR 必须执行当前仓库已有命令：

```bash
python -m compileall -q src
ruff check src tests --quiet
python -m pytest tests -q --tb=line -k "not live_llm"

cd frontend
npm ci
npm test
npm run build
```

规则：

- PR 不得以“只是文档/Schema 小改”为理由跳过；
- 新增 live LLM 评估不能替代 deterministic tests；
- 所有测试默认不访问公网；
- 失败测试必须修复或明确回滚，禁止先 merge 再慢慢看。
