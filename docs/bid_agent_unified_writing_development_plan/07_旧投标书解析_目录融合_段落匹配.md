# 旧投标书解析、目录融合与段落匹配详细计划

## 1. 目标

标书改写不能只把旧投标书作为一大段参考文字。系统必须恢复：

```text
文档
  → 目录树
    → 章节
      → 段落
        → 表格/图片引用
```

并为每个章节和段落建立可追溯语义索引。之后：

- 目录生成参考旧目录子树；
- 章节规划选择具体旧段落；
- Writer 只收到用户确认的原文片段；
- 所有内容都能回到 canonical `SourceBlock.block_id`。

---

## 2. 输入角色与文件规则

新增：

```text
InputRole.LEGACY_BID
```

支持当前 Source normalizer 已支持的办公文档/PDF 类型。业务层允许：

- 一份旧投标书；
- 多份旧投标书；
- 同一旧标书的新版本替换；
- 一份主参考标书 + 多份补充标书。

每份旧投标书保存：

```text
input_id
filename
sha256
version
active
replaces_input_id
```

替换后旧输入保留历史，但 active 索引不再选用。

---

## 3. 结构恢复流水线

### 阶段 1：SourceIndex

复用当前解析器，得到：

- heading；
- paragraph；
- list item；
- table/table cell；
- image；
- page；
- heading_path；
- reading_order；
- content_hash。

### 阶段 2：确定性目录树恢复

新增 `LegacyOutlineRecoveryService`：

1. 过滤 `input_role=legacy_bid`；
2. 按 reading order 排序；
3. 识别 heading blocks；
4. 解析编号；
5. 根据编号和样式/heading_path 推断 level；
6. 建 parent-child；
7. 将父标题后、首个子标题前的正文归入父 section lead；
8. 将段落、表格、图片归入最近合法 section；
9. 记录结构缺口；
10. 输出 deterministic skeleton。

### 阶段 3：语义描述

对 section 和 paragraph 分批调用受控 LLM：

- 只能引用给定 section/block ID；
- 只生成描述和标签；
- 不改原文；
- 不补事实；
- 不生成新章节；
- 输出严格 JSON。

### 阶段 4：污染实体识别

确定性 + LLM：

- 项目名称；
- 建设单位；
- 投标人；
- 地点；
- 日期和年度；
- 工期；
- 人员姓名；
- 数量和金额；
- 产品/平台特定版本；
- 标准号和版本；
- 联系方式；
- 旧评分措辞。

风险记录必须带：

```text
block_id
text span or normalized entity
risk type
reason
replacement policy
```

### 阶段 5：Coverage Gate

验证所有可写正文块：

```text
normalized
or exempt
or structure_gap
```

不得默默丢段。

### 阶段 6：Promotion

`LegacyBidIndex` 通过全局 Proposal/Gate/Promotion。

### 阶段 7：Markdown 投影

晋级后由 Service 根据 active index 生成只读 Markdown。

---

## 4. 标题编号解析

需支持常见格式：

```text
第一章
一、 
（一）
1
1.
1、
1.1
1.1.1
第1节
项目背景（无编号）
```

解析输出：

```python
number_text: str
number_tokens: list[int | str]
level_hint: int | None
title_text: str
```

优先级：

1. parser heading level；
2. 明确多级编号；
3. Word 样式/heading_path；
4. 字体/版式元数据（若现有 parser 提供）；
5. 邻近标题一致性；
6. LLM 只对不确定局部辅助；
7. 无法确定则记录 `structure_gap`，不随意猜。

---

## 5. 章节边界

### 父章节 lead

例如：

```text
2.1 项目任务背景
这里有两段总述
2.1.1 年度变化
...
```

父章节总述必须保存，不能因为存在子标题就消失。投影结构：

```text
section.lead_block_ids
section.direct_paragraph_block_ids
section.descendant_section_ids
```

### 无标题正文

文档开头或标题间无归属段落：

- 建 `document_preamble` pseudo section；
- 或标记结构缺口；
- 不凭空挂到第一个标题。

### 跨页标题

标题和正文跨页仍按 reading order 与 heading path 关联，不用页码作为唯一边界。

### 表格

表格保持整表引用，同时可有 cell block。规划默认选择整表，不允许只拿几个 cell 后丢失表头语义，除非明确生成结构化片段。

### 图片

保存图片 block、标题/附近说明和 source anchor。第一版规划可展示图片存在，不强制让 Writer理解图片内容；需要时单独加入图像理解阶段。

## 6. 稳定 ID

### section_id

建议：

```text
legacy-section:<source_input_id>:<heading_block_id>
```

### paragraph

直接使用：

```text
SourceBlock.block_id
```

### 无 heading pseudo section

```text
legacy-section:<input_id>:preamble:<first_block_id>
```

任何重新排序、分页变化都不能用数组 index 作为 ID。

## 7. 语义描述 Schema

### 章节描述

```json
{
  "legacy_section_id": "...",
  "description": "说明年度调查政策变化、平台支撑基础和国家级核查背景。",
  "answers": [
    "项目产生的政策背景是什么",
    "现有平台提供什么支撑"
  ],
  "content_kinds": ["background", "platform_capability"],
  "reusable_conditions": [
    "新项目仍属于国土变更调查业务",
    "平台名称和版本经核对"
  ],
  "legacy_entity_risks": [...]
}
```

### 段落描述

```json
{
  "block_id": "...",
  "description": "介绍国土调查云平台的任务下发、举证和成果汇交能力。",
  "answers": ["现有技术平台能够提供哪些支撑"],
  "content_kind": "platform_capability",
  "reusable_scope": "可作为平台基础描述，需替换旧项目单位和版本。",
  "legacy_entity_risks": [...]
}
```

描述仅用于检索和解释。Writer 必须读取 block 原文。

## 8. Markdown 投影

建议路径：

```text
workspace/v3/legacy_bid_projection/
└─ <input_id>/
   ├─ README.md
   ├─ outline.md
   ├─ manifest.json
   └─ sections/
      ├─ 002_项目理解/
      │  ├─ _section.md
      │  └─ 002.001_项目任务背景/
      │     ├─ _section.md
      │     ├─ 002.001.001_年度变化.md
      │     └─ ...
      └─ ...
```

每个 Markdown 顶部 YAML 可写：

```yaml
source_input_id: ...
legacy_section_id: ...
heading_block_id: ...
paragraph_block_ids:
  - ...
projection_revision: 1
```

但 Writer 不读取这些文件。它们用于：

- 用户下载；
- 调试；
- 人工核对；
- 回归样本；
- 出错诊断。

投影失败不能让 canonical index 失效；应显示 projection warning。

## 9. 新旧目录融合算法

### 9.1 新招标先生成要求节点

不先直接生成最终标题。对每个评分/招标要求形成：

```text
requirement/score IDs
must-answer
业务主题
期望深度
强制术语
质量约束
模板位置
```

### 9.2 检索旧目录子树

查询由：

```text
新要求标题
must-answer
评分条件
业务主题
```

组成。

候选评分：

```text
title lexical
description semantic
answers overlap
content kind match
parent path match
document priority
risk penalty
```

返回的是 section subtree，不只是单标题。

### 9.3 LLM 融合

模型看到：

- 新要求节点；
- 当前评分组结构；
- 旧候选子树摘要；
- 模板约束；
- stable IDs。

模型输出每个新节点：

```text
title
purpose
writing objectives
score/requirement bindings
outline_lineage
```

### 9.4 确定性校验

继续使用现有：

- ScoreResponseUnit 主责唯一；
- condition 唯一；
- requirement coverage；
- order 连续；
- parent 合法；
- template slot；
- document-level condition 不可见。

新增：

- lineage ID 存在；
- `merged` 至少两个来源；
- `split` 同一旧节点可关联多个新节点；
- template strict 无 topology 变化；
- 旧目录不能增加无依据评分根；
- 忽略节点不出现在 lineage。

## 10. 例子

新招标：

```text
项目任务背景描述清楚（3分）
```

旧目录：

```text
2.1 项目任务背景
  2.1.1 2026年全国国土变更调查新变化
  2.1.2 国土调查云平台支撑
  2.1.3 国家级核查工作背景
```

候选新目录：

```text
2.1 项目任务背景
  2.1.1 本年度调查政策与任务变化
  2.1.2 现有业务平台与技术支撑基础
  2.1.3 上级核查与成果质量监管背景
  2.1.4 本项目实施的必要性
```

lineage：

```text
2.1.1 adapted from legacy 2.1.1
2.1.2 adapted from legacy 2.1.2
2.1.3 adapted from legacy 2.1.3
2.1.4 newly generated from new tender requirement
```

目录阶段不判断最终“全部搬用”。那要到具体段落和搜索材料确认后计算。

## 11. 旧段落候选检索

### 11.1 两阶段召回

第一阶段粗召回：

- section title/description；
- paragraph description；
- content kind；
- answers；
- BM25/向量；
- scope filters。

第二阶段重排：

- content unit must-answer；
- 新招标约束；
- 旧项目风险；
- 段落完整性；
- 邻接段落；
- 表格依赖；
- 重复内容；
- 时效性。

### 11.2 邻接扩展

某段被选中时，应考虑：

- 前一段是否定义术语；
- 后一段是否完成列表；
- 表格前说明；
- 标题 lead；
- 列表连续项。

最终 `selected_fragment_refs` 可以是一个连续 block range，但每个 block ID 都明确。

### 11.3 去重

多份旧标书可能有复制内容。按：

```text
content_hash
normalized text hash
semantic near-duplicate
```

去重，保留来源优先级和可替换关系。

## 12. 多旧投标书规则

工作空间允许设置：

```text
primary legacy bid
secondary legacy bids
```

默认优先级：

1. 用户指定；
2. 更新时间；
3. 结构完整度；
4. 与新项目相似度。

同一个 content unit 选多个旧标书时：

- 必须显示来源；
- 冲突内容标记；
- 不自动合并数值事实；
- rewrite type 通常为 `restructure`；
- 用户可排除某份文档。

---

## 13. 污染防护

### 13.1 规划阶段

来源卡显示风险：

```text
旧项目名
旧年份
旧地点
旧工期
旧人员
旧平台版本
旧标准
```

binding 必须写处理方式：

```text
replace
remove
verify
retain
```

### 13.2 Bundle 阶段

生成：

```text
forbidden_carryovers
```

传给 Writer。

### 13.3 正文后 Gate

扫描：

- 已知旧实体；
- 旧 input 特有 n-gram；
- 过期年份；
- 冲突参数；
- 旧甲方名称。

命中 blocking 风险：

```text
LEGACY_CONTENT_CONTAMINATION
```

不提交草稿，或提交为 blocked preview，具体应与现有 content gate 语义一致。

## 14. 质量阈值建议

| 指标 | 门槛 |
|---|---:|
| heading block 入树率 | 100%，否则明确 gap |
| legacy paragraph 有 section/preamble 归属率 | ≥ 99.5% |
| 可写 paragraph 有 description 率 | 100% |
| description 引用合法 block ID | 100% |
| section parent 无环 | 100% |
| Markdown 投影与 index block 数一致 | 100% 或记录 exempt |
| 随机人工抽检章节边界正确率 | ≥ 98% |
| 旧实体风险召回 | 黄金样本 ≥ 95% |
| 新目录评分条件覆盖 | 沿用现有 Gate，必须 100% |

---

## 15. 测试样本

至少准备：

1. Word 标题样式规范的旧标书；
2. 纯手工编号、无标题样式；
3. PDF 可复制文本；
4. 扫描 PDF；
5. 大量表格；
6. 标题跨页；
7. 父标题 lead 正文；
8. 无编号标题；
9. 多份旧标书高度重复；
10. 旧项目实体密集；
11. 目录与正文标题不一致；
12. 解析中存在 OCR gap。

每个样本保存 expected outline tree 和关键 block IDs，禁止只做“跑完没报错”测试。
